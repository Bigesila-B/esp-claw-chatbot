## Differences from official ESP-Claw

This fork ships on `feature/context-compaction` and is based on upstream [`a4edfe5`](https://github.com/espressif/esp-claw/commit/a4edfe594a99407c8b4d5d70b93906bdd762b745). Upstream already provides Skills, Lua, a QQ bot integration, MCP, and model vision. The table describes the changes in this fork.

| Feature | Upstream baseline | Fork edition |
| --- | --- | --- |
| Enhancements entry | The sidebar provides device settings and chat | Enhancements brings together MCP Settings, Skills, commands, image chat, and session settings. |
| Chat help | Individual commands provide their own help | The Commands page and `/help` in chat show available chat commands, Chinese descriptions, the date, CPU and memory use, today's and this month's token counts, and the LAN address. `/help` in chat also shows context usage for the active session. Manage model connections in the Web Model Settings page. |
| Reply notice | The default route sends “🦞 ESP-Claw is snapping on it...”, and build settings control tool-call progress | The rules used on a fresh setup omit the fixed notice. Web settings can turn tool-call progress on or off at runtime, with progress off by default. |
| MCP | MCP Client and Server capabilities are available | MCP Settings saves up to four named servers with individual connection tests. Supported image jobs send their results back to the original chat. |
| Skills | Skills and Lua scripts are available | Upload Skills from the Web Skills page and see loaded Skills and their unavailable tool groups. Optional MicroPython runs small Python scripts on ESP32-S3 boards with PSRAM. |
| Web images | The upload endpoint accepts up to 512 KiB per file | Web Chat and Files compress larger images in the browser. They prioritize dimensions and detail while keeping the uploaded file within the endpoint limit. |
| Incoming image cache | Incoming attachments are stored in the device inbox | QQ, Telegram, Feishu, WeChat, and Web Chat share a 1 MiB image cache. The oldest cached images are evicted under storage pressure, and failed transfers remove their temporary files. |
| Hosted stickers | Chat platforms provide image-sending tools | `/sticker` looks up and sends a sticker on the device. The device handles links and uses zero model tokens. |
| Cloud image and speech models | Chat platforms can exchange attachments | Configure HTTP image generation, speech synthesis, and transcription in Web settings. Image model drafts created in chat appear in the model list. |
| Cache statistics and reminders | The device can call models and run scheduled tasks | See provider-reported input cache hit rates and manage one-time, interval, and daily reminders in Web settings. |
| Web loading | The device serves the compressed page embedded in the firmware | Serves the full gzip asset so a dropped trailing byte cannot make the page fail to load. |
| Session memory | Compaction starts at a session file size threshold | A context window setting adds a model-dependent compaction threshold. Compaction prioritizes recent turns and tries to summarize older content. |
| Chat recovery | A model failure can surface as a raw error code | Chat shows Chinese messages for timeouts, rate limits, and insufficient space. Send `/retry` to retrieve the last saved answer or retry the last text question in the current conversation. |
| Full storage | A failed session index rebuild can interrupt a reply | If history is unreadable and the index cannot be rebuilt, the device attempts the current reply. Uploads report low storage, and a Skill activation interrupted by full storage can recover after space is freed. |

This fork includes upstream Web conversation history. Refresh to restore chat records saved on the device. Use the sidebar to switch conversations and load older messages by page. [Upstream implementation](https://github.com/espressif/esp-claw/commit/9354591b845371904d043dd4f7258e5f6ee69f61)

## Usage

### Added chat commands

| Command | Action |
|---------|--------|
| `/help` | List commands and show the device date, LAN address, CPU, memory, token counts, and estimated chat context usage |
| `/retry` | Retrieve the saved answer from the current conversation, or retry the last text question after a failure |
| `/sticker [name]` | List hosted stickers or send the selected sticker |
| `/image <prompt>` | Generate an image with the enabled cloud image model |
| `/tts <text>` | Read text aloud with the enabled cloud speech model |
| `/mcp models [offset]` | Read the default MCP server's advertised model catalogue. Paged catalogues accept a starting offset |
| `/mcp last-image` | Resend a recent MCP-generated image from the original chat |

The upstream `/session` menu and replies have Simplified Chinese translations in this fork.

- **Commands and usage.** Open Enhancements → Chat Commands or send `/help` in chat. Web Chat uses the device icon in the help header. The device handles help locally, with zero model tokens. `/help` estimates context tokens from the active session's history and summary and shows the context window and percentage used. Daily and monthly totals come from the model API and are counted from activation onward in the device's time zone. Use the displayed IP address to open the settings page on the LAN.
- **Remove the fixed notice on an existing device.** An upgrade keeps existing routes. If the lobster notice still appears, run `auto rules` in the device's serial console, confirm the rule exists, and run `auto delete_rule im_any_message_working_reply`.
- **Show or hide tool-call progress.** In Enhancements, change Show tool-call progress and save the page. The change applies immediately, and the model can still call tools.
- **Connect to MCP.** In Enhancements → MCP Settings, name each service and enter its Streamable HTTP or legacy HTTP+SSE URL and optional Bearer token. Test each connection and save. Enable MCP Client for the LLM in Capabilities and restart to call tools by server name. Image delivery follows the tool and result fields exposed by the chosen service.
- **Find and use Skills.** Open Enhancements → Skills. When `cap_micropython` is listed, open Web Chat and ask it to use that Skill to run the built-in example with count set to 7. The sample returns a sum of 28.
- **Upload a custom Skill.** Click Upload Skill and choose a folder containing `SKILL.md` or a standalone `SKILL.md` file. The device validates ESP-Claw's JSON format and saves files under `/skills/<name>/`, preserving subdirectories. Click Restart to apply. Existing folders with the same name are protected.
- **Install a Python Skill.** When building, enable `App Claw Config → App Claw Capabilities → Enable MicroPython scripts for Skills` in `idf.py menuconfig`. Declare the `cap_micropython` tool group in the Skill's `SKILL.md`, then call `python_run_script` on `{CUR_SKILL_DIR}/scripts/...`, with JSON input in `args` and results via `print()`.
- **Send a large image.** Select the image in Web Chat and send it when the upload is ready. Files of 512 KiB or smaller are uploaded as-is. For larger images, the browser attempts to preserve dimensions before lowering JPEG quality or resizing as necessary. A PNG converted to JPEG gets a white background, and a compressed animation keeps one frame. Use a vision model that accepts device-uploaded images.
- **Send a hosted sticker.** Send `/sticker` for the catalogue and `/sticker 笑哭` to pick one. Web Chat, QQ, and Telegram send the image. Feishu and WeChat return the image link. To replace the defaults, upload a UTF-8 `stickers.txt` at the root of Files. Write one `name=https://image-host/image.png` entry per line and keep the file within 16 KiB. Each command reads the current file. Default images are from [Twemoji](https://github.com/jdecked/twemoji) by Twitter, Inc. and contributors, licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
- **Send contextual stickers.** Web Chat, QQ, and Telegram can add one fitting sticker to a reply. The model chooses from the first 12 usable catalogue entries during the same reply. In Enhancements, set the sending frequency from 0% to 100%. The default is 50% and applies when the model picks a sticker.
- **Configure cloud media.** Open LLM → Cloud image and speech models. Share the image or speech API URL, model ID, and docs in chat to create a draft, then fill in the key and enable the profile in Web settings. Image generation and generic speech profiles can use media URLs. Image generation can also poll the same provider for an asynchronous job. Select the Xiaomi MiMo TTS preset to decode MP3 or WAV audio and send it to QQ or Telegram. Web Chat keeps the last three generated clips available for playback. Each decoded clip can be up to 128 KiB. For transcription, the device streams audio to the provider. Web accepts audio uploads up to 512 KiB.
- **Configure speech synthesis from chat.** Send `URL: endpoint`, `Key: API key`, and `Model ID: model ID` on separate lines in a private bot chat or Web Chat. The device saves the model as the default for speech synthesis after a successful test.
- **Send automatic voice replies.** Edit a speech synthesis model to enter an optional provider voice ID. Choose Off, Text and voice, or Voice only in Cloud image and speech models. The selection takes effect immediately. QQ, Telegram, and Web Chat use the first enabled speech model and fall back to text if needed. In Web Chat, audio accompanying text plays in the live conversation. In Voice only mode, history shows the original text if the local audio expires.
- **Check cache usage and set reminders.** `/help` shows the monthly input cache hit rate when available. The Chat Commands page shows daily and monthly figures. Its reminders section lets you pick a chat and schedule a one-time, interval, or daily message.
- **Set the context window.** Enter the model's window in Enhancements, save, and restart the device. Use 0 or an empty value to match by model name. The device starts compaction at about 60% of that window, with a fallback threshold of about 150 KiB of session data. Use `/session new` to start a session and `/session list` to see existing ones.

## ESP32-S3 test coverage

Chat help, token counts, MCP tool calls, a custom Python Skill, large Web image uploads, Skill folder uploads, and replies with full storage were tested on an ESP32-S3 with 16 MiB Flash and 8 MiB PSRAM. Local tests covered image cache limits, storage pressure, open files, repeated transfers, and interrupted transfers.

The latest ESP32-S3 test build produced a 3,041,056-byte application image, leaving about 830 KiB in the 3,800 KiB app partition. The board accepted sticker frequencies of 0% and 100%. Image generation and speech synthesis were tested on the board with a local mock API. Transcription passed local mock tests. Check the build output and partition table for your board.

MicroPython is an optional embedded runtime. The test configuration allocates a 256 KiB PSRAM heap, and the runtime supports selected built-in modules and imports from the script directory. A script file can be up to 32 KiB, with a 1-second default timeout, a 5-second maximum, and up to 4,095 bytes of captured output. Skills that rely on desktop Python packages or system commands need adaptation. Use the existing Lua modules and capabilities for device and network I/O.

With full storage, saving new messages to history may fail. If QQ returns `ESP_FAIL`, check Files for large attachments. When reusing an existing `sdkconfig`, set `CONFIG_FATFS_FS_LOCK` to 32 so image cache cleanup can skip open files. Long-session summary behavior still needs validation.
